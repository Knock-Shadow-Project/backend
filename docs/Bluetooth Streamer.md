# Bluetooth Streamer — Documentación

El **Bluetooth Streamer** (`ble-stream`) es el servicio encargado de recibir telemetría en tiempo real desde los guantes inteligentes KnockShadow mediante **Bluetooth Low Energy (BLE)** y persistirla en **PostgreSQL/TimescaleDB**.

---

## Arquitectura general

```
┌─────────────────┐     BLE (GATT)      ┌─────────────────┐     SQL      ┌─────────────┐
│    Saco BLE     │  ─────────────────► │  ble-stream     │ ───────────► │  PostgreSQL │
│  (2 sensores)   │                     │  (Rust/tokio)   │              │  (hypertable│
└─────────────────┘                     └─────────────────┘              └─────────────┘
                                               │
                                               │ INSERT batch
                                               ▼
                                        ┌─────────────┐
                                        │ device_battery_readings
                                        └─────────────┘
```

## Módulos

### `bt.rs` — Comunicación BLE

Este módulo utiliza la librería [`btleplug`](https://github.com/deviceplug/btleplug) para interactuar con el stack Bluetooth del sistema operativo.

#### `connect_device(mac)`

1. Obtiene el primer adaptador Bluetooth disponible.
2. Inicia un escaneo de dispositivos (`start_scan`).
3. Recorre los periféricos descubiertos comparando la dirección MAC.
4. Si coincide, conecta y devuelve el nombre del dispositivo y el handle `Peripheral`.

#### `stream_data(device)`

1. Descubre los servicios y características del dispositivo.
2. Se suscribe a notificaciones de las características cuyo UUID termina en `-0001-11e1-ac36-0002a5d5c51b` y que tengan la propiedad `NOTIFY`.
3. Devuelve un `Stream` asíncrono de `Vec<u8>` con los payloads crudos.

#### `decode_data(payload)`

Decodifica el frame binario recibido del guante:

| Campo | Tipo | Bytes | Descripción |
|-------|------|-------|-------------|
| `ts`  | `u16` (LE) | 0–1 | Timestamp opcional del dispositivo |
| `x`   | `i16` (LE) | 2–3 | Eje X de aceleración (unidades raw) |
| `y`   | `i16` (LE) | 4–5 | Eje Y de aceleración (unidades raw) |
| `z`   | `i16` (LE) | 6–7 | Eje Z de aceleración (unidades raw) |

Los valores `i16` se convierten a `f32` directamente (escalado posterior en el pipeline de Python).

#### `read_battery_level(device)`

Lee el nivel de batería desde la característica estándar BLE **Battery Level** (`0x2A19`).

### `storage.rs` — Persistencia en PostgreSQL

Este módulo implementa un **escritor asíncrono desacoplado** mediante un canal `tokio::mpsc`.

#### Motivación

El loop de lectura BLE no debe bloquearse esperando la escritura en base de datos. `DbWritter` usa un **productor-consumidor**:

- **Productor** (task BLE): envía muestras por el canal.
- **Consumidor** (task writer): acumula lotes y descarga periódicamente.

#### Estrategia de batching

| Umbral | Comportamiento |
|--------|----------------|
| 128 registros | Flush inmediato |
| 50 ms (tick) | Flush si hay datos pendientes |
| Cierre del canal | Flush final y salida |

#### Filtrado de outliers

Antes de encolar, se descartan muestras con `z < -20000.0` o `z > 20000.0` (valores físicamente imposibles para el sensor). Que parece que se los inventa 1 vez por segundo.

#### Esquema de tablas

**`ble_samples`** (hypertable TimescaleDB)
```sql
CREATE TABLE ble_samples (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY,
    device_mac TEXT NOT NULL,
    device_name TEXT NOT NULL,
    ble_ts INTEGER,
    x REAL NOT NULL,
    y REAL NOT NULL,
    z REAL NOT NULL,
    received_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    PRIMARY KEY (received_at, id)
);
```

**`device_battery_readings`**
```sql
CREATE TABLE device_battery_readings (
    id BIGSERIAL PRIMARY KEY,
    device_mac TEXT NOT NULL,
    device_name TEXT NOT NULL,
    battery_level SMALLINT NOT NULL,
    read_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

#### Estadísticas de rendimiento

Cada 5 segundos se imprime por consola:
- Total de muestras escritas
- Tamaño del último lote
- Tasa de escritura (muestras/segundo)

### `main.rs` — Orquestación

El `main` arranca tres tareas concurrentes con `tokio::spawn`:

1. **Conexión BLE** — `bt::connect_device(mac)`.
2. **Stream de notificaciones** — `bt::stream_data(&device)`; decodifica y envía a `DbWritter`.
3. **Lectura de batería** — cada 30 segundos lee y encola el nivel de batería.

#### Variables de entorno

| Variable | Por defecto | Descripción |
|----------|-------------|-------------|
| `DEVICE_MAC` | `DF:65:81:D0:D7:E5` | MAC del sensor BLE objetivo |
| `DATABASE_URL` | `postgres://knockshadow:knockshadow@127.0.0.1:5432/knockshadow` | Conexión PostgreSQL |

## Flujo de datos (paso a paso)

```
1. El sensor envía un paquete BLE de 8 bytes cada ~16 ms (60 Hz).
2. btleplug recibe la notificación y la entrega como Vec<u8>.
3. bt::decode_data extrae (ts, x, y, z).
4. Se crea un BleSample y se envía por el canal mpsc.
5. El writer_loop acumula muestras en un Vec.
6. Cuando se alcanzan 128 muestras (o pasan 50 ms):
   a. Se inicia una transacción PostgreSQL.
   b. Se ejecutan los INSERTs preparados.
   c. Se hace COMMIT.
7. Cada 30 s se lee la batería y se inserta en device_battery_readings.
```

## Notas de despliegue

### Bluetooth en Docker

El contenedor requiere:
- Modo **privilegiado** (`privileged: true`).
- Montaje del socket D-Bus del host (`/var/run/dbus`).
- Montaje del bus USB (`/dev/bus/usb`).
- Capacidad `NET_ADMIN`.

### Compatibilidad de BlueZ

`btleplug` depende de **BlueZ 5.x** en Linux. `bluetoothd` debe estar activo en el host antes de levantar el contenedor.
